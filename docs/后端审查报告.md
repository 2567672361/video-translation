# 后端代码审查报告

> 范围：`backend/`（`server.js` 2019 行、`voice-translation.js`、`local-asr.js`、`local_translate.py`、测试脚本 18 个）
> 方法：静态审查 + 语法检查 + 实际启动 + 接口探测 + 离线测试实际运行

---

## 一、阻断级发现（必须立即处理）

### 1. 真实 API 密钥被硬编码，并已推送到公开仓库

8 个测试脚本中硬编码了仍在使用的真实凭据：

| 文件 | 泄露内容 |
|---|---|
| `backend/test-api.js` | 火山 API Key（`b2197ed8…`） |
| `backend/test-asr.js` | 火山 API Key + Access Token |
| `backend/test-auto-align.js` | APP ID + Access Token + Secret Key |
| `backend/test-doubao-endpoints.js` | 豆包 API Key（`a76d8146…`） |
| `backend/test-doubao.js` | 豆包 API Key |
| `backend/test-full-flow.js` | 火山 API Key + 豆包 API Key |
| `backend/test-proofread.js` | 豆包 API Key |
| `backend/test-translate.js` | 火山 API Key |

- 这些值与当前 `backend/.env` 中的**生产密钥完全一致**；
- 仓库是 **public**，泄露自初始提交 `da30073` 起就存在；
- 仅清理当前文件不够——旧提交仍然可读。

**处置**：立即在控制台轮换全部密钥 → 更新 `.env` → 视需要重写 Git 历史。

### 2. `/preview` 与 `/uploads` 存在目录穿越（已修复）

`path.join(tempDir, req.params.filename)` 未做任何过滤。实测：

```
GET /preview/..%5Ctraversal-probe.txt   →  200，返回了临时目录之外的文件
```

攻击者可读取进程权限内任意文件（`.env`、源码、系统文件）。由于服务监听 `0.0.0.0` 且无鉴权，同一局域网内即可利用。

## 二、已修复项（提交 `c684be4`）

| 问题 | 修复方式 |
|---|---|
| 目录穿越 | 新增 `resolveTempFile()`：`path.basename` + 解析后校验必须位于临时目录内；两个内置流媒体路由均已接入 |
| 上传无上限 | `multer` 增加 `limits: { fileSize: 2GB, files: 1 }` 与 `video/*` 类型校验，非视频返回 400 |
| 启动日志泄露密钥 | 只输出「已配置/未配置」与长度，不再打印 Key 前后 8 位 |
| CORS 配置无效 | `origin: '*'` 与 `credentials: true` 冲突，移除 credentials（本服务不使用 Cookie） |
| 缺少健康检查 | 新增 `GET /api/health`，返回运行时长与队列状态 |

**验证结果**

```
GET /api/health                          → 200 {"status":"ok","uptime":6,"queue":{...}}
GET /preview/..%5Ctraversal-probe.txt    → 404（已拦截）
POST /api/translate-video（txt 文件）     → 400（类型校验生效）
node server.js                            → 正常启动，FFmpeg 自动发现
```

## 四、测试脚本可用性

| 脚本 | 实测结果 | 结论 |
|---|---|---|
| `test-env.js` | ✅ 通过 | 环境变量与硬编码检查正常（已改造为通用检测） |
| `test-simple.js` | ✅ 通过 | Sherpa-ONNX 与模型目录加载正常 |
| `test-ffmpeg.js` | ❌ 失败 | 硬编码样本 `uploads/1775812814483.mp4` 已不存在，脚本过期 |
| `test-ffmpeg2.js` | ⚠️ 假成功 | 同样缺样本，却返回 exit 0，不能作为回归依据 |
| `test-ffmpeg-direct.js` | ❌ 失败 | 字幕滤镜路径未转义 Windows 盘符（测试自身缺陷） |
| `test-video-split.js` | ⏱ >45s 超时 | 真实分段任务，耗时正常但无断言、无清理 |
| `test-simple-api.js` | ❌ 语法错误 | 文件被截断，无法解析 |
| `test-suite.js` | ⏸ 未运行 | 需服务 + 真实 Key，会调用付费接口 |
| `test-api.js` / `test-asr.js` / `test-doubao*.js` / `test-translate.js` / `test-proofread.js` / `test-full-flow.js` / `test-api-upload.js` / `test-auto-align.js` | ⏸ 未运行 | 直接调用线上 API，会产生费用；且依赖的密钥应当轮换 |

**结论**：现有测试大多是一次性调试脚本，不是可回归的测试套件——没有断言、依赖不存在的样本文件、部分返回码失真。真正能作为「测试功能」使用的只有 `test-env.js` 与 `test-simple.js`。

**建议**：新建 `backend/tests/`，用 `node:test` 或 `vitest` 重写：
- 不依赖外网的单元测试（SRT 解析、时间轴合并、文件名校验、上传限制）；
- 用 Mock provider 的集成测试（任务状态机、队列并发）；
- 标记 `@e2e` 的付费用例单独运行，默认跳过。
