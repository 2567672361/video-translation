# 字幕人工编辑 · 改进计划

> 目标：AI 翻译完成后，用户可以在工作台里直接校对字幕（改文字、调时间），保存后重新合成视频。
> 前提：工作台已具备任务系统、源文件保留（24 小时）、视频预览与下载。

---

## 1. 现状与缺口

| 现状 | 缺口 |
|---|---|
| 翻译结果写进 `translations` 表（序号、起止毫秒、原文、译文） | 只有写入，没有读取接口，前端拿不到字幕 |
| 成片已烧录字幕，可预览/下载 | 改动字幕必须重新合成，目前没有入口 |
| 任务详情返回步骤状态 | 不返回字幕、不返回可编辑状态 |
| 源视频在任务结束后保留 24 小时 | 重新合成有了基础，但超期后需要重新上传 |

---

## 2. 用户流程

```
任务完成 → 结果区出现「视频 + 字幕列表」
   ↓ 播放视频，当前字幕高亮，点击某行跳到对应时间
   ↓ 直接改译文 / 微调时间码
   ↓ 保存（校验后写库）
   ↓ 重新合成（后台烧录，进度条走同一套任务通道）
   ↓ 新成片自动替换预览，可下载；也可一键下载 SRT
```

---

## 3. 数据模型改动

`translations` 增加三列（迁移时 `ALTER TABLE` 补齐）：

| 列 | 类型 | 说明 |
|---|---|---|
| `ai_translated_text` | TEXT | AI 原始译文，**不可变**，用于「恢复 AI 版本」 |
| `is_edited` | INTEGER DEFAULT 0 | 是否人工改过 |
| `updated_at` | TEXT | 最近编辑时间 |

`jobs` 增加：

| 列 | 说明 |
|---|---|
| `subtitles_updated_at` | 字幕最后一次保存时间 |
| `render_status` | `idle` / `running` / `failed` / `done` |
| `render_error` | 合成失败原因 |

> 不新建表：字幕天然属于任务，一任务一套字幕，保持简单。

---

## 4. 接口设计

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/jobs/:id/subtitles` | 返回字幕数组：`{ id, sequence, start_ms, end_ms, source_text, translated_text, is_edited }` |
| PUT | `/api/jobs/:id/subtitles` | 整批保存（body：`{ subtitles: [...] }`），服务端校验后整体替换 |
| GET | `/api/jobs/:id/subtitles.srt` | 按当前字幕生成 SRT 下载（不落盘，直接返回文本） |
| POST | `/api/jobs/:id/render` | 重新烧录字幕，异步执行；返回 `202 { renderId }` |
| GET | `/api/jobs/:id/render` | 查询合成状态与进度（前端兜底轮询） |
| POST | `/api/jobs/:id/subtitles/reset` | 恢复 AI 原始译文 |

**整批保存而不是逐行 PATCH**：字幕是与视频同步的整体，整批替换能一次性校验顺序、重叠、总时长，避免半保存状态。

保存校验规则：

1. `start_ms >= 0`，`end_ms <= 视频总时长 + 500ms`；
2. `start_ms < end_ms`，且单条时长 ≥ 200ms；
3. 相邻字幕不得重叠（重叠时自动把上一条的结束时间压到下一条开始前 50ms）；
4. 译文不能为空，单条超过 200 字符时前端提示但不阻断；
5. 条数上限 2000 条，防止误粘贴。

---

## 5. 重新合成流程

```
POST /render
  → 校验：源文件存在？字幕非空？是否有正在跑的合成？
  → jobs.render_status = 'running'
  → 生成临时 SRT（当前字幕）
  → ffmpeg 烧录到源视频
  → 成功：更新 job.video_url，render_status='done'，记录耗时
  → 失败：render_status='failed'，render_error 存首行原因
```

- 进度通过现有 WebSocket 广播，消息形如 `{ type: 'render-progress', jobId, progress, step }`；前端同时用 `GET /render` 兜底轮询；
- 源文件缺失（超过 24 小时清理）时返回 `409`，前端提示「源文件已清理，请重新上传后编辑」；
- 合成期间禁用保存按钮，避免字幕与成片不一致。

## 6. 前端交互（工作台风格）

结果区改为两栏：

```
┌──────────────────────────────┬───────────────────────┐
│  视频播放器（16:9）           │  字幕列表（可滚动）    │
│  当前字幕浮层预览             │  #01 00:00.840-04.586 │
│  ▶ 00:12 / 00:46             │  [译文输入框]          │
│                              │  #02 ...               │
└──────────────────────────────┴───────────────────────┘
   底部：保存 · 重新合成 · 下载 SRT · 恢复 AI 版本
```

细节：

- **时间码**用等宽字体，点击可编辑（`mm:ss.mmm`，支持 `+0.1s/-0.1s` 快捷键）；
- **点击列表行**跳转视频到该条起点；播放时自动高亮当前条并滚动到可视区；
- **译文**为行内输入框，失焦即标记「未保存」，顶部显示脏标记；
- **保存**：前端先做同样的校验，服务端再校验一次；失败返回具体第几条哪一项；
- **重新合成**：按钮变成进度条（复用任务进度样式），完成后刷新视频 URL 并清空缓存；
- **恢复 AI 版本**：仅对改过的行生效，二次确认；
- 键盘：`Space` 播放/暂停，`↑/↓` 切换行，`Enter` 进入编辑，`Ctrl+S` 保存。

视觉沿用现有令牌：琥珀色高亮当前行、`ink` 系列底色、等宽时间码，不引入新组件库。

## 7. 边界与异常

| 场景 | 处理 |
|---|---|
| 编辑中关闭页面 | `beforeunload` 提示；切到历史页前确认 |
| 多人同时编辑同一任务 | 保存时带 `updated_at`，不一致返回 `409` 并提示刷新（先做乐观锁，不做实时协同） |
| 重新合成时再次点击 | 服务端返回 `409`；前端按钮禁用 |
| 长视频合成慢 | 后台任务 + 进度；完成后站内提示，不阻塞页面 |
| 字幕为空 | 禁止保存/合成，提示至少保留一条 |
| 时间码格式非法 | 输入框即时红框提示，不写入状态 |

## 8. 分阶段实施

| 阶段 | 内容 | 验收 | 预估 |
|---|---|---|---|
| P1 | 数据库迁移 + 字幕读取接口 + SRT 下载 + 只读字幕列表（与视频同步高亮） | 打开已完成任务能看到逐条字幕，点行跳转 | 0.5–1 天 |
| P2 | 行内编辑译文 + 时间码编辑 + 整批保存 + 校验 | 改 3 条字幕保存后刷新仍在，非法时间被拦 | 1 天 |
| P3 | 重新合成接口 + 进度 + 视频刷新 | 改字幕→合成→新视频字幕变化 | 1 天 |
| P4 | 恢复 AI 版本、拆分/合并、键盘快捷键、乐观锁 | 全流程可用 | 0.5–1 天 |

**建议顺序**：P1 → P2 → P3，P4 视时间取舍。P1 完成后即可先给你看交互，避免一次性改太多。

---

## 9. 测试计划

- 单元：时间校验（重叠、负值、超长）、SRT 生成格式、恢复 AI 版本；
- 接口：保存后读取一致、并发保存 409、源文件缺失 409、合成状态流转；
- 端到端：Playwright 打开任务 → 改一条 → 保存 → 合成 → 检查视频 URL 变化与字幕内容；
- 回归：现有 12 个后端测试保持通过。

---

## 10. 明确不做

- 不做逐帧可视化时间轴拖拽（成本高，先用时间码输入 + ±0.1s）；
- 不做多人实时协同编辑；
- 不做字幕样式（字体/颜色/位置）在线调整——现有的样式字段先固定，后续单独排期；
- 不做自动重新翻译单条（会引入额外 API 成本，先人工改）。

---

## 11. 风险

| 风险 | 应对 |
|---|---|
| 源文件 24 小时后被清理，无法重新合成 | 合成入口检测并明确提示；后续可提供「保留此任务源文件」开关 |
| 长视频烧录耗时 | 后台任务 + 进度，不阻塞；必要时限制单次合成 2 小时以内 |
| 字幕与成片版本错位 | 保存后标记 `subtitles_updated_at`，合成完成后记录对应版本号 |
| 历史任务没有字幕数据 | 仅对 `succeeded` 且有 translations 的任务展示编辑器 |
